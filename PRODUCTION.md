# Последний автобус — план производства силами агентов

> Дополнение к [GDD.md](GDD.md). Описывает технологии, разбивку работы между агентами, контракты данных и этапы.

---

## 1. Технологии

| Слой | Выбор | Почему |
|---|---|---|
| Язык | TypeScript (strict) | Модели лучше всего пишут на TS. Строгая типизация ловит ошибки между агентами |
| Логика игры | Чистая TS-библиотека `core/` без зависимостей от рендера | Можно гонять в Node тысячами забегов для баланса и тестов |
| Рендер | Сейчас HTML + SVG, позже PixiJS 8 для арта | Прототип на заглушках проще и надёжнее в DOM; PixiJS подключится, когда появятся спрайты |
| UI-оверлеи | HTML/CSS поверх канваса | Меню, карточки событий и тултипы проще верстать, чем рисовать |
| Сборка | Vite | Быстрая сборка, горячая перезагрузка |
| Тесты | Vitest | Юнит-тесты `core/` и прогоны симуляций |
| Упаковка для Steam | Electron + steamworks.js | Стандартный путь для веб-игр в Steam |
| Данные | JSON + JSON Schema | Контент-агенты пишут данные, схема проверяет их автоматически |

Альтернатива — Godot 4 с GDScript. Это нормальный выбор, но headless-симуляции и проверка данных в TS-стеке проще.

## 2. Структура репозитория

```
last-bus/
├─ GDD.md, PRODUCTION.md
├─ core/                 # вся логика, детерминированная, с seed
│  ├─ state.ts           # типы состояния забега
│  ├─ rng.ts             # seeded RNG — единственный источник случайности
│  ├─ map/               # генерация графа, остановки, магазины на перегонах, гонки за узлы
│  ├─ bus/               # слоты, модули, оружие, броня, расход
│  ├─ crew/              # пассажиры, билеты, выход и посадка, посты, уязвимые места, ранения
│  ├─ combat/            # бой тиками (реальное время с паузой), манёвры, попадания, ИИ-профили врагов
│  ├─ rivals/            # обычные враги, заклятый соперник, боссы
│  ├─ events/            # движок событий: условия, выборы, эффекты
│  └─ turn.ts            # шаг хода: маршрут → дорога → узел → салон
├─ sim/                  # headless-бот и прогон тысяч забегов, отчёты по балансу
├─ game/                 # клиент (HTML + SVG, Vite), только читает core и шлёт команды
├─ data/
│  ├─ schemas/           # JSON Schema для всего контента
│  ├─ buses/*.json       # автобусы игрока: сетка мест, посты, слоты
│  ├─ weapons/*.json
│  ├─ modules/*.json
│  ├─ enemies/*.json     # вражеские автобусы и боссы с фазами
│  ├─ drivers/*.json
│  ├─ shops/*.json       # типы придорожных магазинов: ассортимент, цены
│  ├─ events/*.json
│  └─ locale/ru/*.json   # все тексты отдельно от логики
├─ assets/
│  ├─ style-guide.md     # палитра, размеры, правила
│  ├─ sprites/ ui/ backgrounds/
│  └─ audio/music/ audio/sfx/
└─ tests/
```

**Главное правило архитектуры:** `game/` никогда не меняет состояние напрямую. Только отправляет команды в `core/` (`seatPassenger`, `chooseRoute`, `doAction`, `resolveChoice`, `combatTurn`). Тогда любой забег можно воспроизвести по seed и списку команд, а баг от игрока — повторить.

## 3. Контракты данных

### 3.1. Пассажир (в состоянии забега, не в данных)

У пассажиров нет свойств, поэтому отдельных файлов данных для них нет. В состоянии забега пассажир — это:

```ts
type Passenger = {
  id: string;            // уникальный в забеге
  look: LookParts;       // случайный набор деталей внешности, только для отображения
  status: "healthy" | "wounded";
  seat: SeatId | null;   // место или пост в салоне
  ticket: {
    stopsTotal: number;  // 1–5, выдаётся случайно при посадке
    stopsLeft: number;   // уменьшается только на узлах-остановках
  };
};
```

Оплата при выходе: `stopsTotal − stopsLeft` жетонов (раненый — половина, округление вниз). Высадка раньше — 0 жетонов.

### 3.2. Оружие

```json
{
  "id": "wpn_harpoon",
  "nameKey": "wpn.harpoon.name",
  "descKey": "wpn.harpoon.desc",
  "slot": "side",
  "durability": 3,
  "ranges": ["near", "mid"],
  "positions": ["side"],
  "ammoPerShot": 1,
  "reload": 1,
  "shots": 1,
  "damage": 1,
  "effects": [{ "type": "tether", "turns": 2 }],
  "installCost": { "parts": 3 },
  "sprite": "sprites/weapons/harpoon",
  "tags": ["region1", "common"]
}
```

Эффекты описываются данными, а не кодом. Новый тип эффекта добавляет код-агент в движок, контент-агент только использует готовые.

### 3.3. Вражеский автобус

```json
{
  "id": "enemy_prison_bus",
  "nameKey": "enemy.prison_bus.name",
  "kind": "boss",
  "speed": 2,
  "modules": {
    "engine": 10, "wheels": 6, "cabin": 6, "tank": 5,
    "armor": { "left": 6, "right": 6 }
  },
  "weapons": [
    { "weapon": "wpn_mg", "slot": "roof" },
    { "weapon": "wpn_shotgun", "slot": "left" },
    { "weapon": "wpn_ram", "slot": "front" }
  ],
  "ai": "aggressive_rammer",
  "phases": [
    { "trigger": { "hpBelow": 0.5 }, "effects": [
      { "type": "disableWeapons", "count": 2 },
      { "type": "setAi", "ai": "berserk_ram" }
    ]}
  ],
  "loot": { "pick": 1, "from": ["mod_prison_armor", "wpn_riot_cannon"] },
  "sprite": "sprites/enemies/prison_bus"
}
```

ИИ-профили (`ai`) — это код в `core/combat/ai/`. Каждый профиль обязан объявлять **намерение** на ход до разрешения, чтобы игрок его видел.

### 3.4. Автобус игрока

Сетка мест, посты и слоты описываются в `data/buses/*.json`: координаты мест, флаг уязвимости (у борта), к какому слоту привязан пост, какой бронелист закрывает место.

### 3.5. Событие

```json
{
  "id": "ev_road_blockade",
  "kind": "road",
  "weight": 10,
  "conditions": [{ "type": "roadType", "in": ["highway", "dirt"] }],
  "textKey": "ev.blockade.text",
  "choices": [
    {
      "textKey": "ev.blockade.clear_by_hand",
      "requires": { "healthyPassengers": 3 },
      "check": { "chance": 0.7 },
      "success": [],
      "fail": [{ "type": "woundPassengers", "count": 1 }]
    },
    {
      "textKey": "ev.blockade.ram",
      "requires": { "slot": "front", "weaponTag": "ram" },
      "effects": [{ "type": "damageModule", "module": "front", "amount": 1 }]
    },
    {
      "textKey": "ev.blockade.detour",
      "effects": [{ "type": "resource", "fuel": -6 }]
    }
  ]
}
```

Условия выборов опираются на ресурсы, модули, оружие и число здоровых пассажиров — не на свойства людей.

### 3.6. Магазин

```json
{
  "id": "shop_gunsmith",
  "nameKey": "shop.gunsmith.name",
  "weight": 15,
  "regions": [1, 2, 3],
  "stock": [
    { "type": "resource", "resource": "ammo", "amount": [4, 8], "price": 1 },
    { "type": "randomItem", "pool": "weapons", "count": [1, 2], "priceMult": 1.0 }
  ],
  "buysAt": 0.5
}
```

Генератор карты ставит магазин примерно на треть перегонов, не больше одного на перегон. Магазины не уменьшают `stopsLeft` у пассажиров.

Все JSON проходят проверку по схеме в CI. Невалидный контент не попадает в сборку.

## 4. Агенты и их зоны

| Агент | Владеет | Не трогает | Готово, когда |
|---|---|---|---|
| **Ведущий / интегратор** | GDD, этапы, ревью, слияние веток, решения по спорным местам | — | Этап закрыт по критериям |
| **Код: core** | `core/`, `data/schemas/`, `tests/` | `game/`, контент | Тесты зелёные, покрытие ключевых систем |
| **Код: клиент** | `game/`, Electron-обёртка | `core/` (только через команды) | Экран работает на заглушках и реальных ассетах |
| **Баланс / QA** | `sim/`, отчёты, правки чисел в `data/` | Логика движка | Отчёт по метрикам (раздел 6) в целевых коридорах |
| **Контент-дизайнер** | `data/events`, `data/weapons`, `data/modules`, `data/enemies`, `data/drivers`, `data/shops`, `data/locale` | Код | JSON валиден, тексты в едином тоне, у врагов есть намерения |
| **Арт** | `assets/sprites`, `ui`, `backgrounds`, `style-guide.md` | Код, данные | Ассеты по списку, по палитре и размерам |
| **Звук** | `assets/audio` | Всё остальное | Музыка и SFX по списку, нормализованы по громкости |

**Правило:** два агента никогда не пишут в одни и те же файлы одновременно. Каждый работает в своей ветке, интегратор сливает.

## 5. Правила для арт-агентов

Графика рисуется **кодом**: спрайт — матрица символов-цветов, автобусы собираются генератором по параметрам. Подробности — в [assets/style-guide.md](assets/style-guide.md).

- Палитра — `BASE_PALETTE` в `game/art/pixel.ts`; свои цвета у спрайта только для корпуса и одежды.
- Масштаб только целый (×3), `image-rendering: pixelated`.
- Новый враг получает облик одной записью в `ENEMY_LOOKS` (`game/art/buses.ts`) по `id` из `data/enemies`.
- Анимации — CSS: прокрутка дороги, покачивание, вспышки выстрелов и попаданий, дым, огонь.
- Арт-агент меняет только `game/art/` и `assets/`; проверка — глазами в браузере (`npm run dev`) и сборка (`npm run build`).
- **Агент, генерирующий картинки**, работает по [assets/ART-BRIEF.md](assets/ART-BRIEF.md): PNG в `assets/img/`, учёт в `assets/img/manifest.json`, в игру попадают только ассеты со статусом `approved`, остальное рисуется кодом. Инструменты: `npm run pixelize` (исходник → пиксель-арт), `npm run art:check` (в составе `validate`), витрина `/gallery.html`, игра с черновиками `/?art=draft`. Каталог ожидаемых картинок — `game/art/catalog.ts`.

## 6. Метрики баланса (headless-симуляция)

Бот-стратегии в `sim/`: «случайная», «всё в оружие», «всё в броню», «смешанная сборка», «максимум пассажиров», «минимум пассажиров». Прогон по 5000 забегов на каждую. Отдельно — прогон каждого боя (враг × типовая сборка игрока) по 1000 раз.

| Метрика | Цель для MVP |
|---|---|
| Доля побед «смешанной сборки» | 35–50% |
| Доля побед «случайной» | < 10% |
| «Всё в оружие» и «всё в броню» | Ниже «смешанной» |
| Ни одна стратегия не выигрывает больше | 70% |
| Длина обычного боя | 80–180 тиков (40–90 секунд) |
| Победы тактического бота против бота «бей в корпус» | Заметно выше (сейчас 45% против 16%) |
| Победа над боссом 1 у «смешанной сборки», дошедшей до него | 55–75% |
| Погибших пассажиров за забег | 2–6 |
| Жетонов от пассажиров за регион | Хватает на 2–3 покупки в магазинах, но не на всё |
| Доля ходов, когда хотя бы один пост пустует из-за выхода пассажиров | 20–40% |
| Ни одно оружие не стоит в > 60% победных сборок | — |
| Событие не встречается слишком часто | Ни одно событие не выпадает в > 30% забегов |

Отчёт выводится в `sim/reports/<дата>.md`. Агент баланса меняет только числа в `data/`, не логику.

## 7. Этапы

| Этап | Содержание | Кто ведёт |
|---|---|---|
| **M0. Скелет** ✅ | Типы состояния, seeded RNG, генерация карты, шаг хода на заглушках, простейший бот | Код: core |
| **M1. Системы** ✅ | Посты и уязвимые места, билеты, выход и случайная посадка, слоты и модули, расход топлива, магазины на перегонах, движок событий, гонки за узлы | Код: core + Баланс |
| **M1.5. Бой** ✅ (кроме заклятого соперника и банд из 2 автобусов) | Бой тиками с паузой, манёвры, прицеливание по системам, намерения врагов, трофеи, 5 ИИ-профилей, босс с фазами | Код: core + Баланс |
| **M2. Клиент** ✅ (прототип на заглушках) | Экран карты с магазинами на перегонах, салон со счётчиками билетов, рассадка кликами, экран боя в реальном времени с паузой, экран магазина, установка модулей, карточки событий, трофеи, итоги, сохранение | Код: клиент |
| **M3. Контент MVP** ✅ контент, 🟡 арт (пиксель-арт кодом), ❌ звук | 8 видов оружия, 5 модулей, 5 типов врагов, заклятый соперник, босс «Тюремный автобус», 3 водителя, 5 магазинов, 30 событий, тексты на русском | Контент + Арт + Звук |
| **M4. Вертикальный срез** | Все части вместе, баланс в коридорах, 10 ручных забегов человеком | Интегратор |
| **M5. Демо для Steam** | 2 региона, Депо (минимум), английская локализация, страница в Steam | Все |

**Важно:** на M4 нужен живой человек, который сыграет хотя бы 10 забегов. Симуляция проверяет баланс, но не то, интересно ли играть. Это единственное, что агенты не заменят.

## 8. Риски

| Риск | Что делаем |
|---|---|
| Рассадка без свойств пассажиров станет скучной | Людей всегда меньше, чем постов и опасных мест. Враги выбирают цели по бортам, поэтому схема должна меняться от боя к бою |
| Бой сведётся к одной лучшей сборке | Враги с разной бронёй и дистанцией, отчёт симуляции по частоте оружия в победах |
| Бой будет затянутым | Целевая длина в метриках, автоматический пропуск хода, если выбор очевиден |
| Контент от агентов будет однообразным по тону | Единый `tone-guide.md` с примерами хорошего и плохого текста, ревью интегратором выборки событий |
| Арт разных агентов не сочетается | Жёсткая палитра и автопроверка, общий референс-лист в `style-guide.md` |
| Агенты ломают чужие системы | Разделение по папкам, команды как единственный интерфейс, тесты в CI на каждое слияние |
