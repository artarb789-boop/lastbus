# Бриф для ИИ-художника (генерация картинок)

Этот документ — задание агенту, который **генерирует картинки** для «Последнего автобуса». Прочитай его целиком перед первой задачей. Об игре — [GDD.md](../GDD.md), о текущей графике кодом — [style-guide.md](style-guide.md).

## 1. Об игре в двух абзацах

Пустыня после катастрофы. Последний рейсовый автобус везёт людей через выжженные земли от остановки к остановке. Игрок выбирает маршрут по карте, сажает и высаживает пассажиров, покупает топливо, еду и запчасти, ставит на автобус оружие и броню. На дорогах на него нападают другие автобусы: налётчики, конкуренты, таранщики, заклятый соперник. В конце региона ждёт босс — Тюремный автобус.

Бой идёт в реальном времени с паузой, как в FTL. Два автобуса едут параллельно, вид сбоку, оружие заряжается и стреляет по системам врага.

**Настроение:** тёплый жёлтый автобус со светящимися окнами — последний островок жизни в холодном, ржавом, выгоревшем мире. Не мрачно-кровавый постапокалипсис, а грустный и немного уютный дорожный: закат, пыль, самодельные пушки из водопроводных труб, люди в салоне.

**Референсы по ощущению, не для копирования:** FTL (читаемость в бою), Into the Breach (палитра, ясность силуэтов), Mad Max (самодельное оружие на машинах), советские и восточноевропейские автобусы 70–80-х (ЛиАЗ, ПАЗ, Ikarus — форма, не марка). Не рисуй узнаваемые логотипы, марки и персонажей чужих игр и фильмов.

## 2. Стиль

- **Пиксель-арт, вид строго сбоку** (для автобусов и сцены боя), без перспективы и изометрии.
- **Все автобусы смотрят вправо:** нос справа, задний фонарь слева.
- **Чёткий тёмный контур** `#14161b` по силуэту, внутри — 2–3 тона на материал. Без градиентов, сглаживания, размытия, бликов «как на фото».
- **Ограниченная палитра.** Общая палитра ниже обязательна для металла, стекла, огня, теней. Свои цвета — только корпус банды и одежда.
- **Свет:** источник света — закатное солнце слева сверху. Окна игрока светятся тёплым, у врагов окна тёмные.
- **Читаемость важнее деталей.** Врага должно быть можно узнать по силуэту и цвету на размере ×1.

## 3. Технические требования к файлам

Это главный раздел: картинка, нарушившая его, в игру не попадёт.

### Как генерировать

Генераторы картинок не умеют честный пиксель-арт в маленьком размере. Поэтому:

1. Генерируй **крупно**: в 8 раз больше целевого размера или больше. Например, автобус 64×24 → картинка от 512×192.
2. Фон — **сплошной ровный хромакей `#ff00ff`** (или прозрачный, если генератор умеет). Никаких теней на фоне, пола, земли, рамок, текста, подписей.
3. Объект **целиком в кадре**, по центру, с отступом не меньше 5% по краям.
4. Сохрани **исходник** как `assets/img/<папка>/<id>_src.png` и прогони через скрипт:

   ```bash
   npm run pixelize -- assets/img/buses/enemy_rammer_src.png --prompt "текст промпта" --x3
   ```

   Скрипт убирает хромакей, обрезает по объекту, вписывает в размер из каталога (колёса и оружие — к нижнему краю, иконки — по центру), уменьшает блоками и приводит цвета к общей палитре плюс цвета банды плюс несколько своих. Результат ляжет рядом: `enemy_rammer.png`, а с `--x3` ещё и превью `enemy_rammer_x3.png`. Запись в манифесте получит статус `draft`.

   Полезные флаги: `--colors N` — сколько своих цветов разрешить (по умолчанию от 0 у пассажира до 12 у событий); `--extra "#aabbcc,#112233"` — добавить цвета в палитру; `--anchor bottom|center`; `--tol 90` — допуск хромакея (если по краю остались розовые пиксели — увеличь); `--coverage 0.5` — порог прозрачности (меньше — объект «толще»); `--palette none` — не приводить к палитре.

   Ты проверяешь результат скрипта глазами (см. раздел 6), а не только исходник.

Если генератор умеет сразу выдавать пиксель-арт по сетке, сдай и **готовый** файл в целевом размере: его возьмут как есть, если он проходит проверку.

### Размеры (в игровых пикселях, до масштабирования)

Игра показывает графику с **целым масштабом** (×3 в бою и в салоне, ×2 в интерфейсе) и `image-rendering: pixelated`. Поэтому размер готового файла — это ровно размер в игровых пикселях.

| Ассет | Размер готового PNG | Примечание |
|---|---|---|
| Автобус обычный | ширина 44–64, высота 24 | колёса касаются нижнего края |
| Автобус игрока | Рейсовый 60×24, Маршрутка 46×24, Вахтовка 64×24 | без оружия (оружие — отдельные спрайты) |
| Заклятый соперник | 60×24 | |
| Босс | 80×28 | можно выше за счёт надстройки |
| Оружие на корпусе | 16×10 | точка крепления — середина нижнего края |
| Пассажир сидя | 7×9 | вариативность цветом, см. 4.3 |
| Портрет водителя | 32×32 | грудь и голова, взгляд вправо |
| Иконка узла карты | 16×16 | читается на тёмном фоне |
| Иконка ресурса | 12×12 | |
| Иконка предмета | 24×24 | для магазина и снаряжения |
| Иллюстрация события | 160×90 | сцена, без текста |
| Вывеска магазина | 64×32 | |
| Фон сцены боя, слой | 334×70 | на экране ×3 = 1000×210; бесшовный по горизонтали, см. 4.6 |

### Имена и папки

```
assets/img/
  buses/<id>.png          bus_city.png, enemy_rammer.png …
  buses/<id>_src.png      исходник генерации
  weapons/<itemId>.png    wpn_mg.png … (спрайт на корпусе)
  items/<itemId>.png      иконка 24×24 (оружие и модули)
  people/passenger_base.png, passenger_wounded.png
  drivers/<driverId>.png  drv_trucker.png …
  map/<nodeKind>.png      village.png, boss.png …
  resources/<kind>.png    fuel.png, food.png …
  events/<eventId>.png    ev_road_wreck.png …
  shops/<shopId>.png      kiosk.png …
  scene/<layer>.png       sky.png, dunes_far.png, dunes_near.png, road.png
```

- Только `.png`, RGBA, без цветового профиля.
- `id` берутся **ровно** из файлов `data/` (имя файла без `.json`). Новые `id` не придумывай.
- Каждый готовый файл записывается в `assets/img/manifest.json`:

```json
{ "buses/enemy_rammer.png": { "w": 54, "h": 24, "prompt": "…", "status": "draft" } }
```

`status`: `draft` (сделано, ждёт проверки), `approved` (принято человеком), `rejected` (переделать, причина в поле `note`).

### Как картинка попадает в игру

Если в манифесте у ассета `approved`, игра берёт PNG; иначе рисует текущий спрайт кодом. Поэтому можно сдавать по одному ассету, игра не ломается.

- **Витрина** — `npm run dev`, затем `http://localhost:5173/gallery.html`. Там все ассеты каталога со статусом, видом ×1 и в рабочем масштабе рядом с тем, что сейчас рисует код, фильтры по статусу и приоритету, и сборка автобуса игрока со всем оружием по точкам крепления.
- **Игра с черновиками** — `http://localhost:5173/?art=draft`: показывает и `draft`, чтобы увидеть ассет в настоящем бою до утверждения.
- **Проверка** — `npm run art:check` (входит в `npm run validate` и CI): файл есть, размер совпадает с каталогом и манифестом, нет полупрозрачных пикселей, нет забытых файлов без записи.

Каталог ожидаемых ассетов с размерами — [game/art/catalog.ts](../game/art/catalog.ts). Если чего-то нет в каталоге, игра это не покажет.

## 4. Список ассетов

Приоритет: **P1** — видно в каждом забеге, **P2** — часто, **P3** — украшение.

### 4.1. Автобусы — P1

8 штук, таблица цветов в разделе 2. Общее для всех: две оси колёс, фары, задний фонарь, дверь, ряд окон.

- **`bus_city` (игрок).** Городской рейсовый автобус 70-х, жёлтый с охристой полосой, чуть потёртый, но ухоженный. Все окна тёплые. Без оружия — его игра ставит поверх отдельными спрайтами в точки крепления (в игровых пикселях от левого верхнего угла, при ширине 60):

  | Слот | Точка | Где на автобусе |
  |---|---|---|
  | `roof` | (30, 4) | середина крыши — линия крыши должна быть на высоте 4 |
  | `front` | (58, 18) | нос, низ — бампер |
  | `rear` | (2, 18) | корма, низ; оружие зеркалится и смотрит назад |
  | `sideL1` | (45, 13) | левый борт ближе к носу, в окне |
  | `sideL2` | (27, 13) | левый борт ближе к корме |
  | `sideR1`, `sideR2` | (36, 12), (18, 12) | правый борт: рисуется поверх корпуса, но раньше левого и приглушённым |

  Поэтому крыша — ровно на строке 4, колёса — на нижнем крае, окна — примерно строки 7–12. Проверка — сборка на витрине.
Пока сгенерированного автобуса нет, у игрока и врагов оружие рисуется кодом (`game/art/weapons.ts`) и ставится в те же точки. Сгенерированный враг рисуется **вместе со своим оружием**: игра на него ничего не ставит.

- **`bus_shuttle` (игрок, Маршрутка).** Короткий жёлтый микроавтобус, 46×24, лёгкий и юркий, все окна тёплые. Точки крепления те же, но считаются от его ширины (крыша — в середине, борта — на 30–75% длины).
- **`bus_armored` (игрок, Вахтовка).** Вахтовый автобус на грузовом шасси, горчично-хаки, 64×24: высокая посадка, бронелисты по низу, окна тёплые. Тяжёлый и надёжный.

- **`enemy_raider_minibus`.** Короткая маршрутка, красная, в пятнах ржавчины, пулемёт на крыше.
- **`enemy_raider_sawnoff`.** Такая же короткая, ещё ржавее, бурая, из окон торчат стволы обрезов, окна выбиты.
- **`enemy_rival_carrier`.** Синий междугородний автобус, чистый, с нижними бронелистами на заклёпках и логотипом-эмблемой (выдуманной, без текста). Пулемёт на крыше.
- **`enemy_rammer`.** Коричневый, на носу сварной клин-таран, бронелисты, тяжёлый вид.
- **`enemy_siphoners`.** Тускло-зелёный, на крыше бочка с топливом и шланги, канистры привязаны к борту.
- **`enemy_nemesis`.** Чёрный, фиолетовая полоса, белый череп на борту, броня, пулемёт. Должен выглядеть «личным врагом» — самый собранный и опасный из обычных.
- **`enemy_boss_prison_bus`.** Длинный серо-стальной тюремный автобус, решётки на всех окнах, ракетница на крыше, прожектор, отбойник. Самый крупный.

Дополнительно для каждого врага — **P3:** вариант `<id>_wreck.png` (подбитый: дым не нужен, но выбитые окна, сорванные листы). Игра его пока не показывает — это задел для экрана трофеев.

### 4.3. Люди — P1

- **Пассажир** 7×9, сидит, вид сбоку. Сдай **серую базу**, где волосы, одежда и кожа — ровно три серых: волосы `#404040`, одежда `#808080`, кожа `#c0c0c0`. Игра перекрашивает их в цвета внешности каждого пассажира (наборы в `game/art/palette.ts`). Контур, брюки и повязку рисуй цветами общей палитры, они не перекрашиваются. Скрипт для `people/` сам приводит цвета к этим ключам и палитре. Плюс вариант `passenger_wounded` с белой повязкой `#f2efe6` на голове.
- **Водители** 32×32, портрет:
  - `drv_trucker` — Дальнобойщик: крепкий, усы, кепка, клетчатая рубашка, спокойный.
  - `drv_racer` — Гонщик: молодой, очки-гогглы на лбу, куртка с полосами, дерзкий.
  - `drv_guard` — Бывший инкассатор: строгий, бронежилет поверх формы, короткая стрижка, шрам.

### 4.4. Карта и ресурсы — P2

Иконки узлов (16×16): `start`, `village` (посёлок), `garage` (автосервис), `junkyard` (свалка), `checkpoint` (блокпост), `special` (особое место), `encounter` (встреча с врагом), `incident` (происшествие), `boss`.

Иконки ресурсов (12×12): `fuel` (канистра), `food` (консервы), `parts` (гайка и болт), `ammo` (патроны), `medkits` (аптечка), `tokens` (жетон-монета).

Иконки должны различаться **силуэтом**, а не только цветом.

### 4.5. Магазины и события — P2–P3

- **Вывески магазинов** 64×32 (P2): `kiosk` (ларёк у трассы), `gunsmith` (оружейник), `mechanic` (лавка механика), `pharmacy` (аптека), `fleamarket` (барахолка). Надписей нет, только образ.
- **Иллюстрации событий** 160×90 (P3), 30 штук по `id` в `data/events/`. Ключ текста указан в поле `textKey` файла события, сам текст — в `data/locale/ru/events.json` (например, `ev.blockade.text`). Рисуй сцену из текста. Начни с дорожных (`ev_road_*`), они встречаются чаще.

### 4.6. Сцена боя — P2

Четыре слоя, каждый **бесшовный по горизонтали** (правый край стыкуется с левым), готовый размер 334×70, на экране ×3. Слои накладываются по порядку и прокручиваются с разной скоростью (дальние дюны медленно, дорога быстро):

- `sky` — небо с закатом и солнцем, без прокрутки;
- `dunes_far`, `dunes_near` — силуэты дюн, остатки ЛЭП, ржавые указатели, прозрачный верх;
- `road` — асфальт с разметкой и обочиной, прозрачный верх.

## 6. Порядок работы и проверка

1. Возьми один ассет из списка (сначала P1, сначала `bus_city`: он задаёт стиль остальным).
2. Сгенерируй 3–4 варианта, выбери лучший, сохрани исходник.
3. Прогони через `npm run pixelize` (или положи готовый пиксельный файл и сам добавь запись в манифест).
4. Открой витрину и игру с `?art=draft`, посмотри ассет в деле.
5. Проверь **готовый** файл по чек-листу:
   - [ ] размер ровно по таблице;
   - [ ] фон прозрачный, по краям нет розовых пикселей хромакея;
   - [ ] автобус смотрит вправо, колёса на нижнем крае;
   - [ ] контур тёмный и сплошной, нет полупрозрачных «грязных» пикселей;
   - [ ] при ×1 объект узнаётся, при ×3 не рассыпается в шум;
   - [ ] цвета банды совпадают с таблицей, общие — с палитрой;
   - [ ] нет текста, логотипов, узнаваемых марок;
   - [ ] стоит в одном ряду с уже принятыми ассетами (сравни рядом).
6. Запусти `npm run art:check` — он должен написать `Art OK`.
7. Человек ставит `approved` или `rejected` с причиной в `note` (в манифесте). Отклонённое переделывай, учитывая `note`.

**Первая партия для утверждения стиля:** `bus_city`, `enemy_raider_minibus`, `enemy_boss_prison_bus`, `wpn_mg` (спрайт и иконка), пассажир, `drv_trucker`. Остальное — только после того, как эту партию приняли.

## 7. Что ты не делаешь

- Не меняешь код (`core/`, `game/`, `sim/`, `tools/`) и данные (`data/`). Только `assets/img/` и манифест.
- Не ставишь сам себе `approved`.
- Не придумываешь новых врагов, предметов и `id`: если чего-то не хватает, запиши вопрос в `assets/img/QUESTIONS.md`.
- Не используешь чужие игры, фильмы, бренды и логотипы, даже переименованные.
- Не рисуешь интерфейс (кнопки, панели, шрифты) — это задача код-агента.
